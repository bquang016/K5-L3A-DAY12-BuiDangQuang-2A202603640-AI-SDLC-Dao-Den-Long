# Verify Phase Skill

Use this skill at the end of every phase (or after major simulation/contract edits) to guarantee real, reproducible verification before committing or tagging.

## Steps

1. **Run automated verification suite**:
   ```bash
   npm run verify
   ```
   Confirm that:
   - `game.contract.json` (`contract_version: "1.3"`, including `run_cmd`, `bench_cmd`, `soak_cmd`) tuning matches `src/sim/config.js` (`DEFAULT_TUNING`).
   - All `node --test` unit tests (`tests/unit.test.js`) and headless contract tests (`tests/contract.test.js`) pass.
   - Determinism check passes across `--night 1`, `--night 2`, and `--night 3` (byte-identical JSONL output).
   - Full-night headless simulation (`--night 3 --ticks 18000`) completes well within the `<= 30s` budget.
   - Headless soak test (`node scripts/soak.js`) completes with `crashes === 0` and `mem_end_mb <= 1.2 * mem_start_mb`.
   - `node scripts/run.js --export-leaderboard <out.json>` exports valid sorted `{"entries": [...]}`.
   - `npm run build` succeeds cleanly.

2. **Capture real benchmark & soak artifacts (Phase 4 / Release)**:
   ```bash
   node --max-semi-space-size=1 --no-concurrent-recompilation --optimize-for-size --expose-gc scripts/soak.js --seed 7 --nights 10 --out soak.json
   node scripts/bench.js --seed 42 --duration 30 --out bench.json
   ```
   Verify `soak.json` and `bench.json` are generated by real runs without hand-editing.

3. **Record real evidence in `docs/proof/phase-N.md`**:
   - Include only exact observed commands, counts, exit codes, timings, and JSON/JSONL snippets from the current commit.
   - If any manual step (such as recording the `.mp4` demo video or publishing the GitHub Release) happens after the commit, note it honestly rather than claiming it already completed.

4. **Check git cleanliness**:
   - Stage files explicitly (`git add <paths>`); never use `git add -A` or `git add .`.
   - Ensure no `.env`, API keys, tokens, or temporary outputs are staged.
